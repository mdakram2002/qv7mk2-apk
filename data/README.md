# Data provenance and file formats

Production measurements in this directory come from Elexon's BMRS Insights API: FUELHH provides actual generation for `fuelType=WIND`, and WINDFOR provides forecast versions. Raw JSON files contain the returned source rows; the ingestion report records endpoint names, query windows, counts, and retrieval time. Processed CSVs use UTF-8, stable headers, UTC ISO timestamps, and MW values. Null represents unavailable or invalid data; zero is a valid measurement.

Run `python scripts/ingest_january.py` to retrieve the data again and rebuild processed files. Run `python scripts/ingest_january.py --from-cache` to revalidate the committed raw JSON and rebuild without network access. The latter preserves the source retrieval timestamp and labels the report as cache processing. The expected raw files are `raw/fuelhh_wind_january_2026.json` and `raw/windfor_january_2026.json`.

Actual records include `startTime`, `settlementDate`, `settlementPeriod`, `generation_mw`, and `source_dataset`. Forecast records include `startTime`, `publishTime`, `generation_mw`, and `source_dataset`. Matched rows include the decision cutoff, eligible-version count, selection status and reason, selected publication, errors, forecast availability, and data-quality status. Summary rows include expected and matched counts, coverage, MAE, RMSE, bias, and WAPE.

The current cache contains 1,488 actual half-hour intervals and 18,080 January-delivery forecast versions across 744 hourly delivery starts. Accuracy uses the 744 expected hourly starts. The hourly actual for each start is the mean of the two half-hour FUELHH MW values beginning in that hour; it is missing if either source value is missing. At the default cutoff the cache has 744/744 eligible hourly forecasts and 744/744 matched pairs. Actual coverage is separately measured as observed half-hour records divided by 1,488 expected records. The forecast publication search starts 14 days before delivery. In the retrieved sample, the earliest January-delivery version was published on 30 December, and the largest observed lead was about 66.5 hours; this supports the chosen retrieval window for the observed records, but does not prove source-history completeness before 18 December. Invalid and out-of-period records remain in raw files and are counted separately. Exact duplicates are collapsed; conflicting rows at the same key are resolved using a stable sorted-JSON rule and counted in the quality report.
