# Known limitations

- Forecast publication searches in the committed retrieval begin on 18 December 2025. The earliest returned January-delivery forecast was published on 30 December, and the largest observed positive lead was 66.5 hours, so the query window extends well beyond observed WINDFOR lead times. However, the dataset does not establish whether unpublished or older archive rows exist before the search boundary; complete historical publication history cannot be proven from this retrieval alone.
- The retrieved January WINDFOR rows have 744 unique hourly delivery starts. FUELHH has 1,488 half-hour actual intervals. The canonical hourly comparison averages the two half-hour actual MW records for each forecast hour; an incomplete pair remains unavailable. In the checked-in cache at the default cutoff, actual coverage is 1,488/1,488, eligible forecast availability is 744/744, and matched hourly coverage is 744/744. The interval explorer is hourly so its forecast, actual, and error columns are comparable. The actuals export preserves all half-hour source rows. No forecasts are duplicated or interpolated.
- The 10:00 Europe/London day-ahead cutoff is configurable and clearly treated as an analytical assumption. It has not been verified as a procurement gate or contractual deadline.
- A read-only live sample check on 24 October 2026 succeeded against the official FUELHH and WINDFOR stream routes, returning HTTP 200 JSON with the expected fields. The committed raw files were reprocessed from cache; they were not newly ingested live during this audit. The retrieval search starts 12 days before the earliest returned January-delivery forecast and exceeds the largest observed lead, but publication-history completeness before that boundary is not formally established.
- The API loads processed CSVs into memory. It is designed for this small January analysis, not high-concurrency operational use.
- The dataset is copied into the backend Docker image. Files written to Render's default ephemeral filesystem do not survive a redeploy; use a supported persistent disk if ingestion writes need to persist.
- Public requests on 24 October returned HTTP 200 for the Vercel home page, Render health, and Render summary; Render health reported ready, and its CORS preflight allowed the Vercel origin. The deployed summary is still the old implementation (744 matches divided by 1,488 half-hours, 50% coverage, prior metrics). Direct Vercel `/about` returned 404; a `frontend/vercel.json` SPA rewrite has been added locally and needs deployment before rechecking. Other public API pages/exports and incognito access remain unverified.
- The repository is publicly named `qv7mk2-apk`, but its GitHub owner handle is personal and visible. The repository name looks random; ownership is not anonymous.
- No unlisted demo video has been recorded or uploaded. See [video script and recording checklist](video-script.md).
